# Performance findings: `codegraph run` bottleneck discovery (epic #469)

Date: 2026-10-17 (fix round: 2026-10-18) · Branches: `perf/discovery-469` (baseline), `perf/fixes-481-483` (fixes) · Machine: Xeon Gold 6140 @ 2.30GHz, 36 cores, 61GB RAM, Linux
Workload: synthetic mox models (P packages × E entities × 6 scalar props, codelist enum per entity, same-package
`refers` wrap + cross-package `refers` + one `contains` VO each) generated by
`crates/codegraph/tests/perf_model_ladder.rs`; 13-generator api profile; release build.

## 0. A/B after two fix rounds (fixes merged via #486; round 2 on `perf/reopen-and-reads`)

| size | metric | discovery baseline | after round 1 (#486) | after round 2 | total Δ |
|------|--------|----------|-------|------|---|
| 3×8 | cold | 2.26s | 1.25s | **0.45s** | −80% |
| 6×20 | cold | 64.0s | 21.0s | **2.18s** | −97% |
| 6×20 | warm2 | 49.6s | 44.7s | **2.06s** | −96% |
| 9×38 | cold | 832.4s (13.9 min) | 168.2s | **8.27s** | **−99%** |
| 9×38 | warm2 | 404.1s | 366.7s | **8.10s** | −98% |
| 9×38 | ingest GQL | 9,111 (5.3/edge) | 9 | 9 | — |
| 6×20 | generation reads/pass | 15.2k | 11.4k | **8.2k** | −46% |

Warm ≈ cold at every size now — the cache pays for itself again.

**Round 2 mechanisms (and a root-cause correction):**
- **#485 root cause was NOT the reopen.** Characterization (`crates/codegraph-grafeo/tests/reopen_bench.rs`)
  showed the checkpoint reopen is fast and linear (41ms @ 1.4k → 130ms @ 3.9k nodes). The real warm
  killer: **grafeo's v2 file open never rebuilds property indexes** — the catalog section carries index
  names "for reference" but no engine step applies them (only the in-memory `restore_snapshot` path
  does). Every warm MATCH on an indexed property degraded to a full node scan (27–33× per query,
  O(N²) across per-entity workloads) — hence warm slower than cold. Fix (codegraph-side):
  `open_read_only` re-creates `indexed_properties()` after opening (2.5–6.7ms). Bench query workload:
  1,298→48ms @ 1.4k; 3,714→115ms @ 3.9k. Upstream grafeo issue text in #485.
- **Read attribution + first batch slice (#350)**: per-method read counters (`perf::method_read_counts`)
  showed the top volume: `get_entity_names` 1,433/pass, `get_property_ref_target` 1,200 (100% miss),
  `list_schemas`/`list_all_properties`/`get_mox_derived_features` ~660. Landed:
  `list_all_property_ref_targets` batch API (trait + Grafeo + Mock + CachingQuerier bulk-seeding the
  per-key cache) + first-read-wins caching for the four whole-store families. Method calls/pass
  5,519 → 2,235; reads −28.7%; and because the eliminated calls were precisely the O(N) scans,
  wall clock dropped ~10× at 6×20.

**Remaining (now beyond the pain threshold at benchmark scale, tracked in #486-successor issue):**
`get_composition_tree` = ~74% of remaining reads (132 misses/pass × ~46 GQL/tree — the per-tree
`CompositionLoadout` memo doesn't share across trees); raw-engine validation lookups (`get_schema`
480/pass, outside CachingQuerier); 1/entity families only whole-store batches could collapse.

## 1. Ladder — cold/warm wall clock (frozen baseline)

| size | nodes | edges | files | cold (s) | warm1 (s) | warm2 = gen-only (s) | ingest ≈ cold−warm2−checkpoint (s) |
|------|-------|-------|-------|----------|-----------|----------------------|------------------------------------|
| 3×8  | 313   | 126   | 541   | 2.3      | 2.5       | 2.5                  | ~0                                 |
| 6×20 | 1414  | 612   | 2275  | 64.0     | 69.9      | 49.6                 | ~9                                 |
| 9×38 | 3901  | 1728  | 6151  | 832.4 (13.9 min) | 882.8 | 404.1 (6.7 min)  | ~378                               |

Growth 3×8→6×20: nodes ×4.5 → cold ×28.3. Growth 6×20→9×38: nodes ×2.76 → cold ×13.0,
ingest ×~42 for a ×7.8 (V×E) growth — **decidedly superlinear**.

Hotpath-measured split at 6×20 (64.2s cold): **mox ingest 38.5s (60%)**, generation ≈ 25.6s,
validation 0.26s. Warm runs additionally pay a **~24s graph-cache restore** (node-by-node
`apply_document`), which is why warm2 (49.6s) ≈ restore + generation — cache restore costs nearly
as much as fresh ingest at this size.

Benchmark size for future A/B: **6×20** (64s cold — minutes-scale iteration; the cliff is fully visible).
9×38 is the consumer-parity confirmation rung.

## 2. Counter evidence (issues #473; CODEGRAPH_PERF_COUNTERS=1)

| size | ingest GQL calls | edges | calls/edge | generation read GQL | reads/entity |
|------|------------------|-------|------------|---------------------|--------------|
| 3×8  | 699              | 126   | 5.5        | 3,308               | ~138         |
| 6×20 | 3,267            | 612   | 5.3        | 15,235              | ~127         |
| 9×38 | 9,111            | 1,728 | 5.3        | ~42,270             | ~124         |

- Ingest **call count is linear** (5.3× edges, constant) — the superlinear time comes from the **cost
  per call growing with graph size**: every ingest GQL statement pays an unindexed scan of a growing
  node store. `insert_edge` (`codegraph-grafeo/src/ingestor/edges.rs`) does a MATCH before each insert.
- Note: prior to #473 the ingestor never flowed through the `query_gql` choke point — the #389 pin
  counted reads only; ingest volume was invisible until the `CountingSession` wrapper landed.
- Generation is the same disease: ~124 read GQL calls per entity, each degrading with V
  (~0.6ms/query at 313 nodes → ~9.6ms/query at 3,901 nodes).
- Graph-cache checkpoint cost ≈ 50s at 9×38 (warm1 − cold); cache reuse itself works — warm2 adds
  zero ingest GQL calls (verified at counter level). But the restore side costs ~24s at 6×20
  (node-by-node recreate) — see ranked list.

## 3. CachingQuerier hit/miss (9×38, one generation)

Hits dominate within cached families (`get_properties=1416/0` style), but misses still each trigger
queries, and the bulk of volume is in *families that fire most*: `get_ddd_models` 887 hits/run at 3×8
scaling to thousands at 9×38, `get_array_item_schema`, `get_api_resources`, `get_consumed_fields`,
`get_composite_range`. Miss-heavy at every size: `get_property_ref_target` (240 misses at 3×8),
`get_enum_values`, `get_evt_models`. ~124 read calls/entity remain uncached-path queries.

## 5. Ranked bottlenecks → candidate fixes

1. **Unindexed GQL scans paid per call** (root cause; hits ingest AND generation AND cache restore).
   Ingest: 38.5s of 64.2s at 6×20; generation: ~25.6s with 15k reads (~9.6ms/read at 3.9k nodes).
   Fix candidates: Grafeo label/property indexes (AGENTS.md #275 note: "revisit when Grafeo grows
   indexes"); parameterized prepared statements (#412).
2. **Ingest call volume: 5.3 GQL calls per edge.** Fix candidate: batched edge inserts (one statement
   inserting many edges), collapsing the per-edge MATCH.
3. **Graph-cache restore ≈ 24s at 6×20** (node-by-node `apply_document` create_node/set_node_property).
   Fix candidate: bulk restore (or skip restore when a cheaper artifact suffices).
4. **Generation read volume: ~124 uncached reads/entity.** Fix candidates: extend CachingQuerier
   families (miss-heavy `get_property_ref_target`, `get_enum_values`, `get_evt_models`); batch
   querier APIs (#350's approach).
5. **85 GB allocation churn per 6×20 run** — per-call result materialization; shrinks for free once
   call counts drop (items 1–4), revisit if still notable.
